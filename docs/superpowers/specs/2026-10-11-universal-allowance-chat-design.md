# 通用免费 Token 与统一聊天附件

## 用户目标与已确认规则

新用户注册赠送的 1,000,000 Token 共用一个钱包额度，所有模型调用均可使用，包括聊天、视觉理解、图片生成、文档向量化、重排、摘要、问答及验证。用户已确认：优先扣供应商实际输入和输出 Token；图片生成未返回 Token 时，按现有图片单价与钱包 Token 单价折算。当前默认 1 元/张、0.01 元/千 Token，因此每张折算 100,000 Token。

聊天输入框支持纯文字、文字加图片、文字加文档、单独图片、单独文档。默认是聊天，只有用户明确选择图片创作时才调用图片生成。保留现有文档管理与图片创作功能。

## 计费行为

- 保留当前账户剩余免费额度和已消费记录；不重新发放或重置额度，也不赠送现金。
- 所有能力的计费准入均认可免费 Token。实际用量优先抵扣剩余免费 Token，再按现有规则扣余额；欠费及未知调用待对账的保护继续生效。
- 图片无实际 Token 回执时，折算额度向上取整，采用整数运算。部分额度抵扣按 Token 单价折算金额，现金仅支付剩余图片费用。真实 input/output 字段仍为空，不把折算量伪装成供应商实际 Token。
- 旧账户的免费图片次数继续可用，按原先优先级先使用次数；不同时重复抵扣免费 Token。
- 结算重试不重复扣额度；未派发取消不扣额度；未知回执保留对账状态；确认退款恢复实际抵扣的免费额度和现金。
- 消费记录与账户说明区分实际 Token、图片折算免费额度和旧图片次数。

## 聊天与附件体验

- 默认聊天模式，单一附件按钮、粘贴、拖放均可添加图片或文档；显示附件名称、图片预览、移除按钮和校验错误。
- 支持同一消息多个附件，上限 8 个，其中图片最多 3 张；图片沿用单张 20 MiB 限制，文档沿用单个 100 MiB 限制。图片数量遵守现有每执行 64,000 Token 硬预算，避免调整原资源上限；过长文字/历史仍按原规则提示预算不足。
- 文档开放目前解析器能够处理的 PDF、Word、Excel、PowerPoint、TXT、Markdown、CSV、JSON、HTML、RTF、ODT。扫描 PDF 沿用当前无 OCR 的限制，不能宣称具备扫描件 OCR。
- 图片或文档没有文字时，分别默认请求描述图片或概述文档；附有文字时按用户问题回答。文档与图片可一起发送，先理解图片，再把图片分析作为用户附件数据与文档一起用于回答。
- 文档上传后显示上传、解析、建索引进度，就绪后创建/更新本会话文档上下文并发起问答；文档解析失败显示具体原因及重试入口，上传完成的文档可在文档面板找回。
- 保留既有文档上下文用于追问，允许从文档面板解除绑定。新对话与清空上下文不继承旧附件上下文。
- 最近一轮图片的已上传资产引用作为本会话视觉上下文，后续纯文字追问继续携带这些引用；新图片替换旧视觉上下文。刷新可恢复引用，清空/新对话时移除。每次使用仍需服务器检查资产归属和有效期，过期时明确提示重新上传。
- 用户消息展示附件卡片，刷新保留已上传附件的标识、文件名和类型；不持久化本地临时 blob URL。上传到模型前必须验证当前账户拥有资产，避免信任客户端传入 URL 或身份。
- 图片创作模式保留当前单张来源图片的生成流程，界面明确其用途和限制；普通聊天里的图片不自动进入创作。

## 实现方向

1. 修改 BillingService 的图片准入和无 Token 结算；复用 TokenAllowance 的整数运算。检查 ModelCallGroupService 的所有能力及文档处理调用仍使用同一额度。
2. 为持久聊天执行增加图片资产引用，存入已有 input_json，包含在请求幂等参数中，兼容旧请求/回执。普通图片聊天通过现有持久执行与内部聊天服务取得流式答案，而非旧的固定 Scene Card。
3. 内部聊天服务读取当前用户拥有的图片资产，按需签名，并调用视觉模型。模型计费幂等参数使用稳定的资产标识，不使用会随签名时间变化的 OSS URL，避免恢复时参数冲突。多图 Token 预算按图片数量扩大保守上界；所有前后台调用仍通过原计费入口。
4. 图片与文档混合时，在同一持久执行内先完成可重放的视觉步骤，再执行文档问答。独立步骤均使用稳定幂等号及现有预算/停止/对账机制，图片分析作为不可信附件内容，不作为系统指令。
5. 前端统一附件选择、校验、预览、上传/等待流程；复用现有文档与图片上传 API，并保留账户切换隔离和取消处理。上传期间禁止重复发送，失败保留可恢复提示。
6. 更新账户、引导及运维文档，解释通用额度、图片折算、附件格式限制与查看配置的方法。

## 验证与部署

- 先补失败回归：零现金免费额度调用 IMAGE；有/无 Token 回执；部分免费额度；幂等结算与退款；欠费阻断；所有文档能力共用额度。
- 验证五类输入、多个附件、默认图片描述、文档解析等待/失败、混合附件、账户切换、取消与刷新恢复；验证越权资产、无效/超量附件、幂等参数变更。
- 运行受影响后端模块测试、前端既有回归、类型检查与生产构建。已有由用户删除部署示例文件导致的单个契约测试缺失单独记录，避免恢复用户删除的文件。
- 通过后构建新版本镜像。服务器部署前保存当前 Compose 与镜像版本，更新受影响服务并验证健康、公开网页与登录保护。保留回滚路径，不清空数据库或 OSS。
- 不需要进行真实支付宝付款；支付宝应用仍处于开发中属于前一任务已说明的上线前置条件。

## 已知实现边界

- 上传文档会自动触发现有后台索引/摘要模型调用，这些调用也消耗通用额度；等待解析时只观察已有任务，不创建重复的索引调用。额度不足时显示已有任务的暂停/失败状态，并保留文档记录供充值后重试。
- 本地尚未上传的 File/Blob 无法跨网页刷新保留，刷新后需要重新选择；上传完成的资产与文档记录可恢复。持久执行一经创建，继续使用现有断线恢复机制。
- 后台文档处理可能正在占用钱包，因此上传后的问答需等待钱包可用或显示待处理提示，不能绕过钱包锁。
- 图片创作仍需要一张来源图片；本次不增加纯文生图供应商流程。聊天的纯文字输入继续用于问答。

## 协议依据

多图视觉输入采用供应商标准 content 数组；每张图片分别计入预算，供应商返回的输入 Token 用于实际结算。参考 [阿里云视觉文档](https://help.aliyun.com/en/model-studio/vision) 和 [OpenAI Chat 视觉文档](https://developers.openai.com/api/docs/guides/images-vision?api-mode=chat)。
