# 纯文字生图与明确的聊天模式

## 用户目标与已确认选择

用户要求补齐纯文字生图，并明确文本聊天、图片多模态、文件多模态等模式。用户已确认：普通聊天中明确说“帮我生成一张图片”时自动生图，并显示本次使用的模式。沿用现有 React / TypeScript、Spring Boot / Java 21、MySQL 图片任务、OSS 和平台计费体系；继续部署到 boboo.xin，并同步 GitHub 和 README。

## 输入框与实际模式

输入框提供以下五个入口，默认智能聊天。每个入口显示一句用途说明、对应附件约束和示例占位文字；助手消息保存并展示本次实际模式，刷新后仍显示。

| 入口 | 功能与约束 |
| --- | --- |
| 智能聊天 | 文字、图片、文档及混合附件；自动选择文字问答、识图、文档问答；明确生图指令自动创建图片任务。 |
| 文本聊天 | 日常问答与写作，不带入旧图片或文档上下文；拒绝附件并提示更换模式。明确生图指令仍自动转图片生成并显示提示。 |
| 图片多模态 | 图片理解、识别、比较及追问，最多 3 张图片；首轮需要图片，后续可以使用已有图片上下文。明确的单图创作要求转图片生成。 |
| 文件多模态 | 文档概要、检索、问答及追问；首次需要文档，后续可沿用当前文档；允许搭配图片，总附件最多 8 个、图片最多 3 张。 |
| 图片生成 | 只有文字即可生成一张图片，也可附一张参考图片进行编辑；禁止文档和多张参考图；没有参考图时必须填写文字。 |

图片限制仍为单张 20 MiB，文档单份 100 MiB，扫描 PDF 暂不支持 OCR。切换模式不静默丢弃附件；不满足新模式约束时显示原因并阻止发送。

自动生图采用可测试的显式指令识别规则，支持常见中英文生成/画图/编辑图片表达，排除否定指令、关于能力/教程的提问、提示词撰写和代码示例，避免把讨论图片误当作收费生成。明确生图时附件不符合约束则提示修正，不悄悄丢弃附件或回退文字模型。不要求所有纯场景描述都自动判定生图，模糊描述可显式选择图片生成。

## 后端任务与供应商

复用 image_job 和现有租约 Worker。新增需要登录和 CSRF 的创建接口 POST /api/image-jobs，请求包括 requestId、conversationId、prompt 和可选的一张已上传图片资产；增加按 requestId 查询的用户隔离接口。requestId 在租户和用户范围内唯一：同一请求、相同参数返回同一任务，参数冲突返回 409。旧内部创建接口仍兼容，旧任务和旧回执可读。

新增媒体库迁移，允许来源资产/对象键为空，为文生图提供独立输出位置，并增加客户端请求 ID 与请求参数指纹。纯文字任务不读取或签名空的来源对象；参考图任务仍检查所属用户和就绪状态。

DashScope 调用在纯文字时只发送 text 内容，在参考图编辑时发送 image + text，沿用当前平台 IMAGE 模型和凭据。官方接口说明：https://help.aliyun.com/zh/model-studio/qwen-image-generation-and-editing-api-reference 。本次生产验收针对当前 QWEN 供应商；其他兼容供应商至少保证无图片输入时采用文生图请求，不能把 null 塞入编辑请求。

计费继续以任务 ID 幂等预占、派发和结算：优先实际 Token，供应商无 Token 时使用既有图片单价折算，所有模型共享免费额度。任务重读和浏览器刷新不重复生成或扣费。仍保留既有 UNKNOWN 保护与失联回收。

## 浏览器恢复与失败出口

前端在创建前保存 requestId 和请求快照；服务器确认受理后显示任务卡片，解除输入框等待，让用户可继续编辑。实际发送仍遵守现有账户在途消费准入规则，不在本次扩大账户并发额度。生成完成后结果回到对应消息，支持下载及参考图继续创作。

刷新、切换会话、创建接口响应丢失时，按已保存 requestId / jobId 查询并合并对应消息，避免把同一任务附到多个回复。仅对已经保存了完整创建请求且未请求停止的工作做幂等恢复；尚未上传的本地文件明确要求重新选择。停止等待立即释放浏览器忙状态，保留服务端已受理任务，不能承诺取消供应商消费。永久失败显示终态和原因；临时查询失败保留任务；不产生无限阻塞输入框的轮询。

## 实现者选择

五种入口的命名、严格模式不带入其他类别附件、显式指令规则以及任务受理后即可继续编辑是实现者提出的具体交互选择。用户已明确的是纯文字生图、模式清晰、自动生图与本次模式可见；不得把文档内容本身当作可自动执行的生图指令。
